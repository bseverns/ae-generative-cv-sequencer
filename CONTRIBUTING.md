# Contributing

- Keep `SOURCES.md` updated for any external info you add. Include links, retrieval notes, and a short explanation of how the source affected the design.
- If you import third-party code, schematics, artwork, or text, preserve filenames and license headers. If no license is specified, link to the source and seek permission before copying it into this repo.
- Hardware changes should include the KiCad files, generated review artifacts when practical, and a note about AE 0-5 V compliance.
- Firmware changes should include the target sketch, pin map impact, expected behavior, and a short test patch or bench recipe.
- Experiment updates should add measured results to `EXPERIMENT.md` rather than replacing open questions with assumptions.
- Attribution changes should be conservative. Credit people and projects clearly, and avoid naming private individuals without permission.

By contributing, you assert you have the right to contribute under the repo’s license.
